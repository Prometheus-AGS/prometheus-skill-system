# Local acceptance for installation and specification health

Run from the registered Full pack root with `COMPANION_ROOT` pointing at the local Companion checkout. The local wrapper below is proposed in this phase; the specification does not assert that the wrapper exists or the cases passed. Run the positive and negative entries in the adopted final boundary. Exit 0 counts only when the named observations occurred. An unavailable prerequisite, skipped mandatory check, or missing receipt is BLOCKED (exit 2), and a contradictory observation is FAIL. A negative case returns 0 only when the underlying production command detects the intentional defect and the harness verifies the expected ID and cause.

## GREEN-001 · GREEN-01

- **Fixture and isolation.** Record both checkout SHAs and dirty file hashes, release manifest/generation and tested binary hashes/versions. Use two fresh private local installation roots and consumer projects. Give each an independent home, XDG directories, registry, journal, keyring and temporary signer. Use a disposable local macOS user with a separate launchd GUI domain, or an equivalent disposable local macOS VM for the full install. A changed HOME in the operator’s GUI domain is insufficient. Use test-owned service definitions and addresses, and an absent Companion endpoint in the standalone case. Record only public identifiers.
- **Production action.** From Full, run `./install.sh --profile skills --targets agents --non-interactive --yes`, then `./install.sh --verify --profile skills --targets agents --non-interactive`. Repeat with `--profile full` in the independent full-profile domain. Resolve and record the CLI actually used, its release source, and the installed generation. Run unfiltered `prometheus doctor --json` from each registered consumer checkout. Use `prometheus contract show --json`, `prometheus kbd register .`, a uniquely identified `prometheus kbd phase create`, fresh `prometheus kbd status --json` and `prometheus kbd audit --json` in the standalone case. Verify event signatures with the disposable public key. Run the installed `kbd-doctor.sh --check state.kbd-orchestrator --json`.
- **Positive oracle.** Installer verification passes for each profile and the installed expected catalog is readable. Both unfiltered doctor runs meet the criteria in spec.md. Reconcile every original check ID and all ten baseline findings against actual evidence and declared applicability; retained skips must be explicitly optional for this fixture. The full profile must exercise its selected real services and adapters. No omitted or newly required check, empty baseline, or zero applicable mandatory checks counts as a pass. A fresh session reads the exact standalone command ID and signed event, and the isolated KBD projection doctor confirms the same revision. Preserve local regression evidence for the existing `continuity` and `supervision` integration targets, including proof their runnable scenarios executed. Use Companion’s locked package build and `cargo test --locked -p prometheus-substrate --no-default-features --features headless --test continuity --test supervision -- --nocapture` in the isolated domain, with the real pack CLI and legacy pack daemon discoverable. The supervision test’s disposable launchd job must actually restart.
- **Negative control.** In a disposable copy of the valid full install, remove one mandatory installed manifest-listed executable (record the ID/hash) before rerunning the same unfiltered doctor. Require nonzero status and the matching actionable check, e.g. `binaries.manifest`, even though the source checkout and other installed binaries exist. In a configured discovery profile, withhold its real measurement; require the discovery-budget diagnostic and refuse a green gate. Restore the removed inputs and verify the healthy state. Scope changes and cleanup to this isolated fixture.
- **Evidence.** Retain raw JSON, exit codes, profile manifests, check-ID reconciliation and negative-control diagnostics, callable tool hashes, installed evidence, signed readback, and real continuity/supervision outputs with no mandatory skips. Destroy only test-owned roots, temporary identities and service registrations.

## GREEN-002 · GREEN-02

- **Fixture and isolation.** Start with read-only copies of the saved original inventories and clean disposable copies of the real Full and Companion workspaces under test. Record source revisions, source diffs for working-tree builds, the validator locations/versions and input inventory hashes. Use independent caches/configuration and synthetic corpora only for the deliberate negative controls. Validate the genuine tracked and in-scope working-tree inputs for the positive case.
- **Production action.** Run `openspec --version` and `openspec validate --all --strict --json --no-interactive` in both roots with the production baseline version 2.1.1. If Full’s managed release pin differs, run the same validation via the managed runner in its project as well. Parse the full JSON and command exit statuses. Reconcile every baseline type/ID with the final inventory and independently revalidate each claimed successor for documented migrations; preserve the original failing and passing sets. Run `node --test --test-name-pattern="actual OpenSpec apply" scripts/tests/kbd-phase-consistency.integration.test.mjs` with OPENSPEC_TEST_BIN_DIR resolving the selected real CLI and PROMETHEUS_CLI_TEST_BINARY the installed pack CLI; require the named scenario to run. Run `npm run validate:codex` in the real Full checkout to guard the previously passing distribution.
- **Positive oracle.** Strict exit 0 in both roots; zero invalid items, no required strict error or warning silently discounted, every baseline disposition evidenced, previous passing items remain usable, and new items validate. Full covers all 158 original identities or traced legitimate successors. Companion includes `change-cpc-003-companion-workspace`. Capture a per-item ledger with original diagnostics, source-of-truth reference, final requirement/scenario or justified migration, and result. A lower total without this accounting fails the gate.
- **Negative control.** In a separate scratch copy of the now-valid Full workspace, hide all delta files of an identified requirement-bearing change while retaining its proposal/tasks and requiring specs; capture strict rejection and the matching change ID. Independently restore a known placeholder purpose in a now-valid capability and require a strict failure on that specific capability. Restore both inputs before disposal. Verify the baseline comparison itself rejects an omitted baseline identity with no valid successor. A validator crash or failure in an unrelated item is insufficient.
- **Evidence.** Retain raw positive and negative inventories, statuses, actual CLI versions, per-ID reconciliation and evidence for the distribution/apply regression. Remove only the disposable copies and project-local caches when done.
