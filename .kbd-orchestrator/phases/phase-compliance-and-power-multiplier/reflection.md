## Lessons Captured

### L1 — Verify wasm target before proposing

The `wasm32-wasip2` vs `wasm32-unknown-unknown` discovery (change-002 correction in change-003) consumed a full context window. **Before proposing any WASM target**, inspect `Cargo.toml` of the host runtime and check whether it uses Component Model (`wasm32-wasip2`) or core wasmtime (`wasm32-unknown-unknown`). LibreFang uses core wasmtime; the Component Model is for WASI Preview 2.

### L2 — macOS portability is not optional

`timeout` is GNU coreutils, absent from macOS stock environment. Any hook or script that calls `timeout` must be guarded with `if command -v timeout &>/dev/null`. Similarly, `sort -rn` on word tokens sorts lexicographically, not by length — use `awk '{print length, $0}' | sort -rn | awk '{print $2}'`.

### L3 — Type-shape gaps surface at plugin boundary

The `@opencode-ai/plugin` `Hooks.tool` map requires `ToolDefinition` (the Zod-based `tool()` helper shape). The existing tool files used a legacy JSON-schema shape. The bridge pattern — write wrapper functions using `tool()` that delegate to old `execute()` — is sound and avoids touching old files. Document this type contract whenever introducing a new plugin API.

### L4 — rustbpe is Python-only at 0.1.0

Despite the repo being a Rust crate, all user-facing API is via PyO3 Python bindings. There is no stable Rust-native `Tokenizer::from_file` / `Trainer` API in 0.1.0. The correct integration pattern is: Python training → `.tiktoken` export → `tiktoken-rs` Rust inference. Templates should reflect this two-language pipeline, not promise a pure-Rust one.

### L5 — Subagent plan-mode interruption is a workflow risk

Subagents dispatched via `subagent-driven-development` repeatedly entered plan mode and required manual approval, breaking autonomous execution. For this project: prefer direct in-session execution for changes where all design decisions are already resolved. Reserve subagent dispatch for genuinely isolated parallel tasks.
