## Recalled lessons that change ordering, scope or risk

- "`kbd-apply mark-done` updates the task flag but does **not** synchronize the canonical KBD ledger." Every task in this phase is closed with `kbd-apply begin-task`/`end-task`, never `mark-done`, until 06 merges.
- "Verify main includes PR final head after merge." After each merge, the lead checks `git merge-base --is-ancestor <PR head> origin/main` before starting a dependent change. This guards the 03→06 and 04→08 edges.
- "`delivery-cadence` freezes every source named in `ready`…" and "run `git submodule update` before invoking `update-skill-pack.sh`". These apply to any refresh run during execute. No cadence loop runs this phase unless the operator restarts it.
- "For every external integration, run at least one test against the real service." 07 (real Cortex) and 05 (real embedding executor) carry real-service gates. A BLOCKED result is reported as BLOCKED, never as a pass.
- "Avoid reentrant lock-taking CLIs and default fallbacks." This shapes 03 (iteration number read from state.json, no default) and 06 (reconcile reads files and never calls the cadence CLI).

## Execution rules

- Implementation first: complete each change, then run its `verify.sh` once. Use package-scoped Rust targets (`cargo test -p … --test …`), never bare `cargo test`.
- Before any cargo command, check `pgrep -x cargo || pgrep -x rustc`; `verify.sh` refuses to start otherwise. Workers do not run ad-hoc cargo builds. Only the lead runs cargo, and 02's build starts only after 05's `verify.sh` has exited.
- Tests use a scratch HOME, CODEX_HOME, CORTEX_DATA_DIR and PROMETHEUS_PLUGIN_ROOT. The real `~/.claude`, `~/.codex`, `~/.cortex`, `~/.prometheus` and the live `:23001` are never written by a gate.
- Outward-facing steps need explicit operator approval in chat. That covers the surreal-memory-server v1.10.1 tag push, any version pin bump in the skill pack, and PR merges, which are the user's. Branch pushes and PR creation follow the previous phase's workflow: the lead pushes feature branches and opens PRs, and the user reviews and merges. Two machine-local steps also need approval at the phase boundary: running 02's installer step against the real `~/.codex`, and replacing the local git-ignored `.prometheus/cadence/procedures/refresh-skill-pack.sh` with 03's shim. Gates never do either.
- Reviewers stay dormant until a change's production work is complete. The phase-final integration boundary works on merged main, in order:
  1. rerun every change's `verify.sh`;
  2. with approval, refresh the machine (`update-skill-pack.sh --force` and `install-binaries.sh` from a deploy worktree), which installs the new `prometheus` CLI and, once the 1.10.1 tag is approved and pushed, surreal-memory 1.10.1;
  3. run `prometheus doctor --json` live and confirm `codex.memories`;
  4. install the cadence shim, with approval.
