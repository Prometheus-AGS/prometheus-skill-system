# Release history and upgrades

Start with the version in the root `package.json` of the Full checkout you installed. The pack, its CLI, individual skills, native services and Companion have separate versions. For example, the Full 1.17.0 macOS ARM64 bundle contained a working `prometheus 1.15.0` CLI. Keep the source revision alongside the pack version when diagnosing a difference. [Download receipt](https://github.com/Prometheus-AGS/prometheus-skill-system/blob/30e63d55/.kbd-orchestrator/phases/vlbv-r4-portability/children/intersession-communication/evidence/release-download-sample.json)

## Choose a source or binary

For an exact historical source tree, use a published Git tag or a commit linked above. For a native executable, open the pack’s Releases page, select the pack version and check the attached assets for your OS and architecture. A changelog entry records a source change. A Git tag identifies a source revision. A GitHub Release can exist with only the automatic source archives. The installer verifies published checksums during native asset acquisition. [Git tags](https://github.com/Prometheus-AGS/prometheus-skill-system/tags) · [Published releases](https://github.com/Prometheus-AGS/prometheus-skill-system/releases) · [Native installation](19-installation.md)

Before activating the new version, note the active generation, selected home and service providers. Keep backups of the databases and identities your workflows use. Then follow the normal update procedure and run the check for your selected profile. A generation rollback restores skill payloads and their projections. Native services and persistent databases have their own recovery procedures. [Updating](20-updating.md) · [Service recovery](26-service-operations.md)
