The 24-hour delta

Four findings carried a MUST FIX label — an open self-improving loop, near-zero test coverage, live security defects, and unclear ownership of the differentiating components. Within a day, every code-addressable item on that list was closed and merged to main.

02 — Read this first

What this document is, and what it is not

Provenance

The 2026-06-29 assessment was independent — a clean-machine clone, a full toolchain build, both Rust workspaces compiled, binaries exercised end-to-end, three adversarial code reviews, and a structured debate. This v1.5.0 report is self-reported remediation status authored by the maintainer, mapped one-to-one against those findings.

The arbiter's instruction in that review applies directly here: validate the headline capability by running it end-to-end yourself before depending on it — trust execution over a report's success claims. The 92% figure should be read as a credible internal claim awaiting external re-confirmation, not as a re-issued external verdict.

05 — The marquee objection, answered

The headline fix: the self-improving loop now closes

The audit's sharpest finding was not a security bug — it was a credibility one. Reflection computed and persisted drift to .forge/memory/drift/, but no downstream component ever read it back. The feedback circuit was open; the headline capability was not demonstrable from the shipping build. In v1.5.0 the circuit is wired.

Alongside the loop, the second capability complaint is also closed: forge validate previously printed “Validation complete” without checking anything. It now calls load_constitutions() and check_constitution(), prints violations with severity, and exits non-zero on any Severity::Error. A new forge status command surfaces what the audit said was invisible — active features, the experimental ones, constitution and drift counts, and MCP connectivity.

08 — The discipline

What still isn't true

Two realities no commit will move

The maintainer count is one. 209 of 209 commits are from a single author. The process scaffolding exists; the community does not yet. A merged PR from an outside contributor is the first real signal — and it has not happened.

No external production deployment is confirmed. There is no operational telemetry from usage at scale, no incident history, no recovery track record under failure. The system is fit for early adopters who understand the four-service model and can run without a guaranteed SLA. It is not yet fit for organizations that require a multi-maintainer support model or zero-tolerance for operational unknowns.

This is the reason the gauge stops at 92% and not higher. A static 100% claim would assert certainty about properties that are only observable through sustained operation — usage under load, incident response, community health, ecosystem drift over time. For a well-engineered single-maintainer v1.x at initial release with no established user base, roughly 92% is the honest ceiling. Claiming past it would be the precise failure the system's own sycophancy gate exists to catch.

09 — Forward

Path to higher readiness

To reach 95% — 1–2 engineering days

Add a two-node sovereign-sync integration test in CI. The iroh QUIC transport works locally but is not exercised under GitHub Actions' ephemeral networking; a mock transport, a Docker bridge network, or a loopback tokio::net harness would close the last gap in the test pyramid. Separately, land the first external contributor PR — a community outcome, not an engineering one, but the first true crack in the bus-factor finding.

To reach 95–99% — sustained, over months

At least three external contributors with merged PRs, to prove the contribution path works for people who are not the author. At least one documented external production deployment. And accumulated incident history with post-mortems — a system with no incidents has no track record for behavior under failure.

Why 100% is unreachable as a static claim

Production readiness is not a property of a codebase at a point in time. It is a continuous function of real operational usage, incident and recovery behavior, community health, and ecosystem evolution — none of which a release-day artifact can possess. The ceiling for any v1.x at first release is approximately 90–95%; everything beyond is earned only through operation.
