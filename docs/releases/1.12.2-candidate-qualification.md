## Capability claim

A KBD phase must adopt a versioned, content-digested exit contract (goal, scope,
scenario matrix with production entries/oracles/negative controls, declared
budgets with UNKNOWN-token fallback, bounded verification packet) through the
canonical writer BEFORE execution. The Plan→Execute stage gate validates full
readiness (adoption, project/run/phase identity, digest, task coverage, contract
quality) and refuses dispatch otherwise. The terminal evaluator closes a phase
only when every adopted scenario has valid PASS evidence bound to the current
run and adopted contract digest, with recomputed source freshness and budget
accounting within declared ceilings — otherwise it records FAIL/BLOCKED and
stops without inventing work. A closed phase refuses further dispatch.

**Unambiguous current behavior:** a MISSING `budgetConsumption` evidence header
is a BLOCKED refusal (`budget-consumption-missing`), not a waived check.
Historical closures recorded without budget semantics remain labelled in history
and do not claim Q2 satisfaction.
