# Why

UI work currently receives inconsistent skill guidance, and creating a team does not reliably make that team discoverable by subsequent coding sessions. The operator approved a shared, offline UI routing contract and explicit project-team installation across the full pack, Windows-native mini pack, and The Boss.

## What Changes

- Bundle a pinned, attributed UI catalog with a portable subset and declared full-only capabilities.
- Add shared UI routing, bounded Impeccable core adaptation, automatic review guidance, and a TypeScript 7 Pro Max port.
- Install short instruction pointers through bootstrap and the existing UI rule injector.
- Extend the existing team runtime with safe project installation and default role adoption while preserving proposal-only export.
- Integrate source generation, mini distribution and The Boss packaging; preserve its existing team and design authority.
- Persist research evidence, limitations and deferred engine-port designs. Verify only after the complete production phase.

## Capabilities

### New Capabilities
- `ui-ux-routing`: selective context, direction, craft and platform routing with portable packaging.
- `project-team-defaults`: managed project-team installation and native or sequential role adoption.

### Modified Capabilities

None. Existing bootstrap and distribution interfaces are extended compatibly.

## Impact

Primary implementation lives in isolated mini and full worktrees based on the existing agent-team-creator commits. The Boss receives its own bounded integration. This user-authorized change spans these three repositories only. Runtime boundaries are local files, upstream pinned content and harness adapters; no new service, telemetry, runtime downloads or engine dependencies are added to mini. Native Windows evidence must remain pending unless actually executed.
