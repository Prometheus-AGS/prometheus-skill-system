## Purpose
Provide a shared offline UI skill contract that preserves incumbent design authority and selects only relevant portable guidance.

## ADDED Requirements

### Requirement: Selective UI routing
The system SHALL load context first, focused Pro Max intelligence, one craft skill and manifest-matched platform guidance. It SHALL distinguish new, redesign, refinement and review; only new/redesign MAY select at most one taste implementation and one explicit overlay. Backend work SHALL load no UI guidance.

#### Scenario: Refining a nested Flutter screen
- **WHEN** refinement targets an application with a pubspec.yaml inside a larger repository
- **THEN** Flutter guidance and existing tokens are selected without a taste skill or automatic design-system replacement.

#### Scenario: Model-aware direction
- **WHEN** new visual direction is requested and the actual model family is GPT
- **THEN** gpt-taste is selected; the harness name alone SHALL NOT imply GPT.

### Requirement: Portable offline catalog
The catalog SHALL identify immutable upstream revisions, licenses, aliases, assets, invocation restrictions and adaptations. Mini SHALL contain no executable Python, shell hooks, native skill engines, symlinks or runtime downloads. Deferred native capabilities SHALL NOT be advertised as implemented.

#### Scenario: Packaged offline use
- **WHEN** The Boss executes a packaged helper with its Node runtime and optional services are down
- **THEN** bundled routing and Pro Max data remain usable without a source checkout or developer-global skill.

### Requirement: Managed project instructions
Bootstrap and the UI injector SHALL use the same protocol, preserve project overrides and unrelated prose, preflight all writes and retain recovery information.

#### Scenario: Corrupt instruction markers
- **WHEN** either entrypoint contains malformed or duplicate managed markers
- **THEN** installation refuses before changing project files.

### Requirement: Review and design authority
Automatic review SHALL respect upstream user-only invocation restrictions, avoid taste-driven redesign, preserve DESIGN.md and execute at the completed phase boundary.

#### Scenario: Independent review unavailable
- **WHEN** the harness cannot create a separate reviewer context
- **THEN** the limitation is recorded and builder self-review is never reported as independent review.
